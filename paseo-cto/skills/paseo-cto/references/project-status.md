# Founder project status

Use this reference only when the founder asks where the project is or how much remains. Read the
actual project plan and accepted evidence; do not load fleet, command, charter, or task references.

Answer in the founder's language, briefly and without technical detail. Localize the labels below:

```markdown
Project status — <date/time>

Current strategy: <alpha|beta|stable>
Readiness: <N>% toward <explicit target>
Remaining: <N>% · <count> major waves
Primary constraint: <one short sentence or none>

| Epic / wave | Status | Ready |
| --- | --- | --- |
| <plan-aligned name> | <planned|running|blocked|done> | <N>% |

Conclusion: <where the project is and what must happen next, one or two sentences>
```

Show three to seven aggregate rows, but calculate readiness over every in-scope top-level outcome.
Use project weights when defined; otherwise equal weights across that complete set. Count accepted
outcomes, not activity or elapsed time. If scope or acceptance is incomplete, report readiness and
remaining as `unavailable`, never approximate them. Name the percentage target explicitly; `100%`
toward alpha exit is not stable-release readiness. Explain any readiness change caused by a changed
denominator. Strategy may be reported to the founder but is never sent to workers.
